Actual release path reproduced
The tag-triggered release workflow configures Go from go.mod, QEMU and Buildx, then
runs GoReleaser release --clean. That publishing command was NOT invoked locally.
.goreleaser.yaml compiles ./cmd/exporter with CGO_ENABLED=0 for Linux amd64/arm64,
using -s -w -X main.Version={{.Version}}, and packages both with Dockerfile.release.
The latter copies the prebuilt binary into gcr.io/distroless/static:nonroot; it
sets USER nonroot:nonroot, ENTRYPOINT /ollama-exporter and ports 9400/9401.
The multistage Dockerfile (golang:1.26.9-alpine builder) is not the published image
path and was not substituted. Instead, the unmodified Dockerfile.release was built
by local rootless Podman using the configured flags and corresponding prebuilt
binaries. A local smoke version was stamped consistently into binary/image labels:
  0.0.0-ollama-container-build-ksmnvx63
GoReleaser's before-hook was checked with go mod tidy -diff: exit 0, no changes.
Each target base was pulled and inspected immediately before a --pull=never build;
the final image's base-layer prefix was verified against that inspected base.

Final actual-image matrix and assertions
- Native generate/chat: JSON and NDJSON (four cases).
- OpenAI /v1/chat/completions and /v1/completions: JSON with/without usage, streams
  include_usage true/false/omitted (ten cases).
- Anthropic /v1/messages: JSON/SSE with/without usage (four cases).
- Native generate and OpenAI chat: client cancellation, upstream disconnect after
  first content and non-2xx error fidelity (six cases).
- Every completed response preserved exact bytes (hash evidence), status 201/503,
  Content-Type, X-End-To-End and X-Final trailer. Request body and authorization
  forwarding were checked by hashes, not retained contents. Seven-byte writes
  fragmented JSON/SSE; SSE included CRLF/comments and native final JSON had no LF.
- Fourteen streams reached the client while the mock's completion gate was still
  closed. A ten-second read/deadlock deadline bounds failure, not a 100ms target.
  Observed local-mock first-content times were 0.833-1.380ms; this is not a latency
  SLA or real-model first-token benchmark.
- 24 duration observations, 18 successful inference completions, 24 terminal
  extraction observations and zero in-flight at the final barrier. Each request
  checked its deltas exactly once; cancellation/disconnect/error cases completed
  duration accounting without fabricated inference completion/token observations.
- Native fixture: 100 / 4 seconds = 25 decode tokens/sec and 16 / 0.125 seconds =
  128 prefill tokens/sec. Compatibility responses did not add native durations;
  reported 16/100 usage created the separate count histograms. Eight missing-usage
  cases produced usage_absent and no token observations. Endpoint/model/family/
  quant labels were checked against the synthetic fixture values.
- Client transport shutdown caused mock request-context cancellation. Upstream
  ErrAbortHandler disconnects remained incomplete/broken client streams; error
  status/body forwarding remained faithful. All mock requests reached completion
  before the shutdown phase; no test request remained hung.
- Idle SIGTERM shutdown exited 0 in 0.136 seconds, without forced kill or OOM.
  Both exporter ports were confirmed closed afterward. Active-stream SIGTERM
  draining was not separately tested; cancellation/disconnect cleanup was.
- Fresh prompt/response/secret markers were generated only in memory. Logs and
  scraped metrics were scanned for those literal markers BEFORE retention. No
  marker appeared in logs or metric labels. Only body hashes/counts/deltas were
  retained. This is a focused synthetic leak check, not a general log-content audit.

Isolation and cleanup
Each attempt used uniquely named rootless containers and --internal networks.
Host publications (including mock control) were ephemeral and bound to 127.0.0.1;
backend inference used mock-ollama over the private network. Only generated config
was mounted read-only. No host networking, privileged flag, Docker socket or
production mount was used. All attempt containers/networks/mock image names were
verified absent, including failed attempts. The two local release-test image names
were matched to recorded IDs before targeted removal, then verified absent.
No broad prune was run. Public base-image/build-layer caches and /tmp evidence
payloads remain; they are not running containers or deployed services.

Failures retained, not hidden
The original prepared recipe generated an invalid uppercase local repository name
from mktemp; stderr/command/status 125 are retained in initial-build-failure/. The
smallest correction lowercased only the temporary identifier in a new local recipe.
An initial Python helper shadowed the http module; two subsequent readiness attempts
waited for an intentionally one-hour poll and expired before any inference cases.
The corrected fixture uses a one-second polling interval. Host proxy injection was
also disabled as test isolation. Those zero-case failure reports and successful
cleanup logs remain under smoke-01/02/03. smoke-04 passed 24 cases; smoke-final
repeated the matrix after adding extraction/capability/absence assertions. These
were test-harness issues; the exporter and release packaging were unchanged.

Remaining limitations
Runtime coverage is amd64 and MOCK-ONLY. Existing Ollama 0.40.3 / gemma3:4b live
checks in earlier reports used host exporter binaries and are separate evidence.
This private-network run did not probe container-to-host Ollama reachability or
repeat live inference. No Ollama binding/network settings were changed, no service
was started/restarted and no model was downloaded. Live thinking-model/Open WebUI
behavior remains untested. This smoke suite does not replace the retained parser
memory/race/large-event tests or imply prevention of every regression. GoReleaser
itself, CI publishing, registry upload, signatures and multiarch manifest publishing
were not executed; local images reproduced the configured release Dockerfile,
static binaries, platform and label flags without publishing.
