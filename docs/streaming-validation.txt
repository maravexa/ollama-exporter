Behavior and semantics
POST /api/generate and /api/chat preserve response bytes and native throughput
semantics. No whole-response or whole-line allocation occurs. ReverseProxy uses
immediate flushing. Duration recording is deferred and ErrAbortHandler propagates.
Upstream read errors and early Close never synthesize completion observations.
Request duration now includes request-prefix inspection and excludes the final
model metadata lookup. Requests whose initial body read fails return 400 and still
receive one duration observation unless their path is excluded.

POST /v1/chat/completions, /v1/completions, and /v1/messages support JSON and SSE.
/v1/messages/count_tokens is forwarded without inference extraction. Compatibility
counts use separate input/output token histograms; missing/null usage is unobserved,
and explicit zero is observed once. No native timing or wall-time TPS is invented.
Completed compatibility responses increment requests_total even without usage.
Requests, including stream_options.include_usage, are forwarded unchanged.

Remaining limits
The parser permits nesting through 64 levels, retains selected scalar values
through 4096 encoded bytes, and ignores field names beyond 128 encoded bytes.
Structural/selected-value limits disable metrics while preserving forwarded bytes.
Request model lookup examines at most 64 KiB. A later model uses the query value
or empty duration/in-flight model label; a response model still supplies inference
labels. This behavior has a regression test. Compatibility SSE requires clean EOF
and a terminal marker; an otherwise useful usage frame without terminal completion
is deliberately not counted. Usage can be unavailable depending on Ollama version
and route; the exporter does not alter requests to obtain it.
Benchmarks below measure parser allocations for generated inputs, not total
process RSS, network buffers, or long-lived model-cache/metric cardinality.
These tests do not establish that all possible regressions are prevented.
